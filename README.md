# git-backfill

GitHub 贡献图补全工具：**建一个私有仓库，让每天都有一个拟真提交，推上去把历史绿墙填满**。

## 它是怎么工作的（先看这个，30 秒）

工具会在本地生成一个 git 仓库（默认 `backfill-out/`），按日期范围给**每一天**造
1~4 个提交——时间是伪造的过去时间点，消息是拟真的小改动（`docs: fix typo` 之类），
然后把整个仓库推送到你 GitHub 上的私有仓库。

GitHub 按**提交上写的时间**（而不是推送时间）统计贡献，所以推完之后，过去那段日子的
绿墙就亮了。

运行工具需要三类信息，配置一次就够：

| 信息 | 说明 |
|---|---|
| **你是谁** | 提交用的名字 + 邮箱。邮箱必须和 GitHub 账号绑定（Settings → Emails 里能看到的），否则格子是灰的、不计数 |
| **推到哪** | 你私有仓库的地址，如 `git@github.com:用户名/仓库名.git` |
| **补哪段** | 日期范围。不指定就是"整个可见绿墙（约 371 天）、到昨天为止" |

这些信息存在配置文件 `backfill.json` 里，**之后 `fill` 不带参数也能跑，就是因为它会自动读这个文件**。

## 快速开始

### 第 0 步：在 GitHub 上做准备（只做一次）

1. 新建一个**私有空仓库**：New repository → 选 Private → 命名（比如 `my-notes`），
   **不要**勾选 README / .gitignore / License（仓库必须是空的）
2. 查一下你的 noreply 邮箱：Settings → Emails → "Keep my email address private" 那段话里，
   形如 `数字ID+用户名@users.noreply.github.com`——那串数字是你账号专属的用户 ID，
   **每个账号都不一样，照抄页面上显示的原文即可**（推荐用它，不暴露真实邮箱；
   用登录邮箱也可以，只要它在绑定列表里）
3. Settings → Profile → 勾选 **Private contributions**（不勾的话私有仓库的绿点只有你自己看得见）

### 第 1 步：写入配置（只做一次）

```bash
python git_backfill.py config --email 你的邮箱 --name 你的用户名 \
    --remote git@github.com:你的用户名/你的仓库名.git
```

执行后当前目录出现 `backfill.json`，长这样（也可以之后用记事本直接改）：

```json
{
  "name": "你的用户名",
  "email": "你的邮箱",
  "remote": "git@github.com:你的用户名/你的仓库名.git"
}
```

### 第 2 步：补墙

```bash
python git_backfill.py fill
```

不带参数 = 补最近 12 个月。它会依次：**生成计划 → 显示每月活跃度让你确认 →
在本地仓库生成提交 → 推送到你配置的私有仓库**。中途问 `[y/N]` 时输入 `y` 回车
（不想被问就加 `--yes`）。

只补某段时间（比如只有某个月是空的）：

```bash
python git_backfill.py fill --start 2020-09-01 --end 2020-09-30
```

推完等几分钟到几小时，打开 GitHub 个人主页看效果。

## 配置文件 backfill.json

作用：把每次都要敲的参数存下来，命令行只写临时变化的部分。

- **放哪**：运行命令的目录或脚本所在目录（都会自动找）；也可 `--config 其他路径`
- **查看**：`python git_backfill.py config`（不带任何参数就是查看）
- **修改**：再跑一次 `config` 命令带上新值（只覆盖给的项），或直接编辑 JSON 文件
- **优先级**：命令行参数 > 配置文件 > 内置默认。比如配置里 email 是 A，某次
  `fill --email B` 只那一次用 B，配置文件不变
- 含个人邮箱，已默认加入 `.gitignore`，不会被误提交

全部可配置项（都不填也行，有默认值）：

| 命令行参数 | 配置键 | 默认 | 说明 |
|---|---|---|---|
| `--email` / `--name` | `email` / `name` | git 全局配置 | 提交身份；邮箱必须绑定 GitHub 账号 |
| `--remote` | `remote` | 无 | 私有仓库地址；配置了就自动推送 |
| `--start` / `--end` | — | 昨往前350天 / 昨天 | 日期窗口；**未来日期硬拒绝**（封号重灾区） |
| `--repo-dir` | `repo_dir` | `backfill-out` | 本地仓库目录，会一直保留、可反复追加 |
| `--out` | `out` | `fill-plan.json` | 计划文件位置 |
| `--lang` | `lang` | `en` | 提交信息语言 `en` / `zh` |
| `--fill` | `fill` | `empty` | `empty` 空提交 / `devlog` 日记文件（有真实 diff） |
| `--frequency` | `frequency` | `1.0` | 每天有数据的概率；`0.85` = 偶尔断更更像真人 |
| `--seed` | `seed` | 随机 | 固定后同样的命令生成完全一样的计划 |
| `--paint` / `--paint-level` | `paint` / `paint_level` | 无 / `3` | 在绿墙上画 5×7 点阵文字，如 `--paint HELLO` |
| `--no-weekends` | `no_weekends` | 关 | 周末留空不提交 |
| `--yes` | — | 关 | 跳过所有确认 |

## 后续继续补格子

本地仓库（`backfill-out/`）会一直保留。过段时间想让新日子也变绿，**再跑一次 `fill`
选新的日期段**即可——提交自动追加到原历史后面并重新推送（remote/repo 都在配置里，不用重写）：

```bash
python git_backfill.py fill --start 2020-11-01 --end 2020-11-30
```

也可以随时手动往这个仓库提交真实内容（日记、笔记等），和工具生成的历史互不冲突。
注意工具拒绝未来日期，只能"过一天补一天"，别想着提前把明年的格子填了。

## 分步用法（想精细控制时）

```
fill  =  plan(生成计划)  ->  apply(按计划生成提交)  ->  push(推送)
```

`fill` 只是把这三步串起来。每一步都是独立子命令，`plan.json` 是唯一事实源；
apply 支持**断点续跑**（中断后重跑同一命令自动跳过已完成的）。

## 拟真设计（为什么它不太像假的）

- **三保险时间戳**：`GIT_AUTHOR_DATE` + `GIT_COMMITTER_DATE` + `git commit --date` 同时设置
- **工作时段加权**：上午/下午/晚间三峰 + 5% 深夜档，同日提交间隔 20 分钟以上，绝不整点
- **提交消息池**：`docs: fix typo` / `style: format code` / `chore: cleanup` 等常规式随机组合
- **强度错落**：每天 1~4 个提交加权随机（55/28/12/5），绿墙深浅自然

## 风险须知（必读）

- GitHub 官方禁止滥用贡献图，**过量提交、未来日期是风控重灾区**。本脚本硬拒绝未来日期，
  总量 >2500 会警告；别贪多
- 推送后绿墙刷新需几分钟~几小时
- 建议用**新建的私有空仓库**接收，不满意整个仓库删掉即可，绿点也会随之消失
- 本工具仅供学习 git 机制与个人存档用途，后果自负
